# Подпись Windows

`author: Dreamer` — метаданные приложения. Подтверждённый издатель в Windows определяется сертификатом Authenticode, а не этим полем. Имя издателя должно соответствовать проверенным данным владельца сертификата; произвольное имя в `publisherName` не создаёт доверенную подпись.

Без сертификата сборка остаётся неподписанной. Самоподписанный сертификат не убирает предупреждения у обычных пользователей. Даже доверенная подпись не гарантирует немедленного исчезновения SmartScreen: он отдельно учитывает репутацию файла и издателя.

## Подключение сертификата

Если центр сертификации предоставляет сертификат с ключом в формате PFX/P12, в настройках GitHub → Secrets and variables → Actions добавьте:

- `WIN_CSC_LINK` — содержимое файла сертификата в Base64.
- `WIN_CSC_KEY_PASSWORD` — пароль сертификата.

Закрытый ключ и пароль не следует добавлять в репозиторий или присылать в чат. Для аппаратного токена или облачного сервиса потребуется подключение по инструкции выбранного поставщика: универсальный PFX-экспорт может быть недоступен.

Workflow автоматически выбирает подписанную сборку, когда задан `WIN_CSC_LINK`. `forceCodeSigning` запрещает незаметно выпустить неподписанные файлы при ошибке сертификата. После сборки PowerShell проверяет доверенную Authenticode-подпись установщика и `Nimbo.exe`; при ошибке релиз не публикуется.

Для локальной сборки с настроенными переменными окружения:

```bash
npm run build:signed -- --publish never
```

Обычная `npm run build` без сертификата создаёт неподписанную сборку для проверки. Workflow явно сообщает об этом в журнале. Код не отключает проверку подписи обновлений: при подписанной сборке electron-builder записывает издателя из сертификата в `app-update.yml`, а electron-updater проверяет его перед установкой следующей версии.

## Обновления

Для каждого релиза нужны установщик `.exe`, его `.blockmap` и `latest.yml`. Workflow публикует их вместе. Не заменяйте файлы опубликованной версии: выпустите новый номер версии, чтобы контрольные суммы и кеши оставались согласованными.

Установленный Nimbo проверяет стабильные релизы и скачивает новую версию в фоне. SHA-512 сверяется с `latest.yml`; для подписанной сборки также проверяется издатель. Установка начинается только по кнопке «Перезапустить и обновить». NSIS запускается с `/S --updated --force-run`, без страниц мастера, после чего открывает Nimbo. Профиль, закладки и сеансы сайтов сохраняются. Прежняя установка «для всех пользователей» может потребовать UAC.

Новый механизм появляется в версии 3.1.1. С 3.0.0 потребуется один раз обновиться прежним способом. Разработческая версия и другие платформы не скачивают и не запускают Windows-установщик.
